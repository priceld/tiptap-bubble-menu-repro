BubbleMenu: a destroyed view's focus timer steals focus

When the editor gains focus, BubbleMenuView schedules setTimeout(() => this.update(...)), and destroy() never cancels it. ProseMirror destroys every plugin view whenever the plugin list changes. So if anything calls registerPlugin while the editor takes focus, the dead view's timer still fires.

The editor below has a bubble menu for editing a link's text. It opens when the caret is in a link and moves focus into its input, ready to type.

Steps

  1. Click Reset. This puts the caret inside the link without focusing the editor, so focus stays on the button.
  2. Press Tab to move focus into the editor.

Expected: the menu opens with the link text selected in its input, ready to type over.
Actual: the menu opens, but focus ends up on <body>. Typing goes nowhere.

With this checked, the steps above lose focus. Clear it and repeat them, and the input keeps focus.
