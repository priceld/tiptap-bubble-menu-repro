BubbleMenu: two ways the menu gets stranded on screen

Two independent defects with the same symptom, both in BubbleMenuView. Stock configuration — no custom shouldShow. Related to #6210, whose reported cause (preventHide) accounts for only the second of the two.

Reload between the two sequences. The log below tells them apart: Bug 1 logs one editor blur and Bug 2 logs two.

Bug 1 — nothing listens for focus leaving the menu

  1. Select some text in the editor. The bubble menu appears.
  2. Click Button A. Focus moves into the menu and the menu stays open, which is correct.
  3. Click the dashed area.

Expected: the menu hides. Actual: it stays.

The content element lost focus at step 2, so it cannot blur again. blurHandler is bound to editor.on('blur') and there is no focusout listener on the menu element, so step 3 runs no code at all. The log shows a single editor blur, from step 2.

Control: reload, then do steps 1 and 3 only. The menu hides correctly, so nothing about the click target is to blame.

Bug 2 — a stale preventHide swallows a real blur

Reload first.

  1. Select some text in the editor. The bubble menu appears.
  2. Click Button A. mousedown set preventHide, and the blur it caused consumed the flag.
  3. Click Button B. The content is already blurred, so this mousedown sets preventHide again with no blur to consume it. The flag is now stale.
  4. Press Escape. Focus returns to the content with the selection intact, and the menu stays open.
  5. Click the dashed area.

Expected: the menu hides. Actual: it stays.

Unlike Bug 1 a real blur does arrive here — the log shows a second editor blur — and the stale flag makes blurHandler return before reaching hide(). Fixing Bug 1 does not fix this: focus is on the content at step 5, not in the menu, so a menu focusout listener never fires.
